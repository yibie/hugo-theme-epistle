# PR/FAQ — Wanglai / 往来

状态：Final（2026-08-01）

## Press Release

### Headline

> Wanglai 让任何 Hugo 博客拥有不要求访客登录、由作者决定公开内容的私人往来

### Subtitle

> Cloudflare 接住匿名来信，私人 GitHub Issues 承担收件与审核；作者用一个 `publish` 标签，将适合公开的来信与可选回信变成博客原生内容。

### Date

> 2026 年 8 月

### Intro paragraph

Wanglai（往来）是一套面向 Hugo 博客作者的开源、自托管来信系统。它不把博客改造成公开评论区，也不要求读者拥有 GitHub 或社交账号。访客可以直接写信；原始内容与邮箱只进入作者的私人收件仓库，作者决定哪些内容适合出现在文章末端的“往来”中。

### Problem paragraph

传统评论系统通常要求第三方登录，或者让匿名内容直接进入公共讨论区。前者阻止读者开口，后者带来垃圾评论、持续审核和隐私压力。通用表单服务可以把消息送到邮箱，却不能自然完成阅读、回复、择选公开和沉淀为博客内容的完整流程。

Hugo 作者还面临安装成本：评论组件往往绑定特定主题、托管服务或数据库。作者需要的是一个能接入现有主题、数据仍由自己控制、日常只需处理私人 GitHub Issues 的小系统。

### Solution paragraph

Wanglai 使用 Cloudflare Worker 与 Turnstile 提供公开提交入口，使用始终独立的私人 GitHub inbox 仓库存放原始来信，再由 GitHub Actions 把经过作者批准的白名单字段写入 Hugo 源码仓库。Hugo Module 提供中性的模板与最小样式，主题可以直接覆盖。`publish` 是最终批准动作：它直接生成并推送一条经过净化的 Markdown 内容，不需要创建或合并 PR。

### Company leader quote

> “往来不是另一个评论区。读者需要一条不用注册就能写信的路径，作者需要一只私密、可审核、能把少数交流留下来的信箱。Wanglai 只连接 Cloudflare、GitHub 和 Hugo 已经做好的能力，不再造数据库和后台。”

### How the product works

1. 作者从 Wanglai 模板创建一个始终独立的私人 inbox 仓库，并连接自己的 Hugo 源码仓库。
2. 作者部署 Cloudflare Worker、配置 Turnstile，并以 Hugo Module 接入中性模板或覆盖为自己的主题样式。
3. 访客填写称呼、可选邮箱与正文。表单明确提示：既然来信，内容就有可能被作者公开；邮箱等私人字段永不公开。
4. Worker 在服务端验证请求，并把原始来信写为私人 inbox 仓库中的 Issue。
5. 作者可直接发布访客来信，也可先在 Issue 评论中以 `/reply` 开头写下公开回信，再添加 `publish` 标签。
6. Action 为该 Issue 创建一条独立的净化内容提交，通过仅限 Hugo 源码仓库的写入凭据推送到默认分支，并触发现有部署流程。
7. 如需撤回，作者必须对对应发布提交执行 Git revert。Wanglai 同时提供一个简单脚本，帮助作者校验目标、创建 revert 并推送；不另设 `unpublish` 状态或删除通道。

### Customer quote

> “读者不必注册，我也不用维护一个公开讨论区。每天只看私人 Issues；值得留下的交流加一个标签就会出现在博客里，撤回时仍有完整的 Git 记录。”

### How to get started

> 使用 `github.com/yibie/wanglai` 的安装模板，连接 GitHub 与 Cloudflare，并按 Hugo Module 文档完成首次来信测试。

## FAQ

### Internal FAQs

#### Wanglai 是留言板或评论系统吗？

不是。它服务于“私人来信、作者择选公开”的单向编辑流程，不提供公共线程、读者账号、点赞或实时讨论。博客中的公开区域称为“往来”。

#### 为什么公开入口必须位于 Cloudflare？

GitHub Actions 和 Issues 不是匿名 HTTP 服务，把 GitHub 凭据放进静态页面也不安全。Cloudflare Worker 接收请求并持有 Secret，Turnstile 在服务端完成验证；Cloudflare 是产品固定边界，不抽象其他运行时。

#### 为什么 inbox 仓库必须与 Hugo 源码仓库分开？

inbox 保存原始正文、可选邮箱和审核记录，源码仓库只接收允许公开的白名单字段。强制分仓可以让源码仓库无论公开还是私有，都不会因为错误配置而包含原始私人数据。

#### 为什么使用 GitHub Issues，而不是数据库或管理后台？

私人 Issues 已提供持久化、标签、评论、通知、搜索与审计记录，足够覆盖个人博客的低频来信。复用它能减少安装和维护成本；只有真实规模超出 Issues 时才重新评估存储。

#### `publish` 的精确含义是什么？

`publish` 是最终批准。添加标签后，Action 读取当前 Issue 和首条有效 `/reply`，生成净化 Markdown，并直接推送 Hugo 源码默认分支。回复不是发布前提；没有 `/reply` 时只公开访客来信。重复运行必须幂等。

#### 为什么使用 deploy key 写入 Hugo 源码仓库？

每个安装实例都需要跨仓库写入，而首版不提供托管 GitHub App。写入凭据仅授权目标 Hugo 源码仓库，并只存放在私人 inbox 的 Actions Secrets 中。发布内容必须经过字段白名单，绝不复制邮箱、IP、Turnstile token 或内部元数据。

#### 为什么首版不兼容要求 PR 的严格分支保护？

首版把“加 `publish` 标签后无需人工合并”作为核心体验，因此要求发布凭据能写入源码默认分支。必须经 PR 合并的仓库不属于首版的无 PR 路径；后续只有出现明确需求时才增加兼容模式。

#### 如何撤回已经公开的往来？

每次发布只对应一条独立 Git 提交，并把提交链接回写到私人 Issue。撤回的唯一机制是对该提交执行 `git revert` 并推送，由正常博客部署移除内容。Wanglai 提供一个薄脚本完成目标校验、revert 与推送；脚本不调用另一套删除 API，也不维护额外状态。直接删除生成文件不是受支持的撤回流程。

#### 为什么不提供 `unpublish` 标签？

Git 已经提供可审计、可再次反转的撤回记录。再引入标签状态会制造 Git 与 Issue 两套事实来源，并增加并发和幂等边界。首版只以发布提交及其 revert 为准。

#### 如何支持任意 Hugo 主题？

Hugo Module 提供语义化模板、最小中性样式和稳定内容字段，不依赖 Epistle 的布局或视觉变量。主题作者可以覆盖模板与 CSS；首版不为每个主题增加专用适配代码。

#### 如何支持未来的其他博客系统？

首版只实现 Hugo，并固定一份最小的“已批准往来”数据契约。不会预先建立插件 SDK 或注册中心；第二个真实博客系统出现后，再从两个实际实现中提取适配边界。

#### 初版明确不做什么？

不做公共评论线程、访客账号、实时聊天、点赞、附件、AI 审核、自建管理后台、数据库、SaaS、多租户、Hugo 以外的发布器，以及严格分支保护下的 PR 发布模式。

#### 如何发布和升级 Wanglai？

项目采用 MIT 许可证与语义化版本。安装模板和工作流引用已审阅的发布版本或提交 SHA，升级由作者主动执行；不会静默跟随默认分支。

#### 怎样判断首版成功？

- 熟悉 GitHub 与 Cloudflare 的 Hugo 作者能在约 20 分钟内完成安装和首次测试来信。
- 访客无需账号即可投递，且提交前能看到可能公开的提示。
- 原始邮箱与内部元数据不会进入 Hugo 源码仓库或公开构建产物。
- 作者仅通过私人 Issues、可选 `/reply` 和 `publish` 完成日常发布，不需 PR、合并或手动 push。
- 同一 Issue 重复触发不会生成重复内容。
- 任意 Hugo 主题可以使用默认模板，并能通过覆盖模板/CSS 完成定制。
- 单条公开往来可以通过对应发布提交的 Git revert 撤回，辅助脚本留下可审计的 revert 提交。

### Customer FAQs

#### 访客需要 GitHub 登录吗？

不需要。GitHub 只出现在作者侧的私人收件与发布流程中。

#### 访客必须填写邮箱吗？

不必须。邮箱只用于作者私下联系，永不进入公开内容；不填写时作者仍可在博客中发表公开回信。

#### 来信会自动公开吗？

不会。提交时会提示内容可能被公开，但只有作者添加 `publish` 标签后，净化版本才会进入博客。

#### 作者必须回复才能公开来信吗？

不必须。作者可以直接发布访客来信；如果 Issue 中存在首条有效 `/reply`，它会与来信一起公开。

#### Hugo 源码仓库必须是公开仓库吗？

不必须，可以公开或私有。只有 inbox 仓库必须私有，并且始终与源码仓库分开。

#### 必须使用 Epistle 主题吗？

不需要。Wanglai 是主题无关的 Hugo Module，默认界面保持中性，并允许主题覆盖模板与 CSS。

#### 必须使用命令行工具或 Wanglai 托管服务吗？

不需要。首版通过 GitHub 模板、Actions、Cloudflare 部署流程和 Hugo Module 完成自托管安装，不提供 CLI 或 SaaS。

#### 服务成本是多少？

Wanglai 本身按 MIT 许可证免费开源，并以个人博客低流量为目标。Cloudflare 与 GitHub 的实际额度和费用以用户账户及平台当期政策为准。

#### 发布错了怎么办？

从私人 Issue 打开该次发布提交，按文档运行 Wanglai 的撤回脚本。脚本使用 Git revert 留下反向提交并推送，博客随后按正常流程重新部署。
