# Spec — Wanglai / 往来（Approved）

依据：`pr_faq_wanglai-standalone_20260801.md`（Final）

## Summary

将现有往来能力抽取为主题无关、MIT 授权、自托管的 Hugo 项目。Cloudflare Worker 接收匿名来信；始终独立的私人 GitHub inbox 仓库存放原始内容；作者以可选 `/reply` 和最终 `publish` 标签，把净化 Markdown 直接写入 Hugo 源码仓库。

## Goals

- 访客无需账号即可投递，并在提交前获知内容可能公开。
- 原始来信、邮箱与内部元数据只存在于私人 inbox。
- 作者在 GitHub Issues 中完成阅读、可选回复和发布。
- `publish` 后无需 PR、合并或手动 push。
- 以主题无关的 Hugo Module 提供语义模板与最小中性样式。
- 每次发布对应独立 Git 提交；撤回必须使用 Git revert，并提供简单辅助脚本。
- 安装方式保持自托管，不引入 Wanglai SaaS、CLI、数据库或管理后台。
- README 与完整安装、运维、数据契约文档均提供分开的英文和简体中文版本。

## Non-goals

- 公开评论线程、访客账号、点赞、实时聊天与附件。
- AI 或自动内容审核。
- Hugo 以外的博客发布器。
- 严格要求 PR 的默认分支保护兼容模式。
- `unpublish` 标签、直接删除生成文件或第二套撤回状态。
- 多租户托管平台与提前设计的适配器 SDK。

## Actors and Boundaries

- 访客：只接触博客表单与 Cloudflare Worker，不接触 GitHub。
- 作者：管理私人 inbox Issues、Hugo 源码仓库和 Cloudflare 配置。
- Cloudflare：固定公开入口，执行 Turnstile 与请求边界验证。
- 私人 inbox 仓库：原始来信、可选邮箱、审核状态、公开回复及发布提交链接的唯一收件记录。
- Hugo 源码仓库：只接收经过白名单净化的公开 Markdown，可以公开或私有。
- Hugo Module：渲染表单和文章末端“往来”，允许主题覆盖模板与 CSS。

## User Flows

### 安装

操作：作者从模板创建私人 inbox，连接 Hugo 源码仓库，部署 Worker 并启用 Hugo Module。  
反馈：健康检查与测试来信确认 Worker、Issue 创建、发布和 Hugo 构建均可用。  
回退：任一步失败时不写入公开内容；文档按边界分别提示 Cloudflare、GitHub 权限或 Hugo 配置问题。

### 访客来信

操作：访客填写称呼、可选邮箱与正文，通过 Turnstile 后提交。  
反馈：表单明确提示来信可能公开；成功后显示已送达，不暴露 Issue 地址。  
回退：校验或上游失败时保留用户正文并给出可重试反馈，不把失败请求视为已送达。

### 作者直接公开来信

操作：作者阅读私人 Issue 后添加 `publish`。  
反馈：Action 创建单条净化 Markdown 提交、推送源码默认分支，并把提交链接回写到 Issue。  
回退：验证或推送失败时移除/标记未完成的发布状态并给出可诊断日志；不得写入部分私人数据。

### 作者公开来信与回信

操作：作者先发表首行是 `/reply` 的 Issue 评论，再添加 `publish`。  
反馈：首条有效公开回复与来信一起生成；其他评论保持私有。  
回退：无有效 `/reply` 时按“仅公开来信”处理，不阻塞发布。

### 重复触发

操作：相同 Issue 再次触发发布工作流。  
反馈：结果幂等，不重复创建内容；若公开字段发生允许的变更，行为必须在实现计划中明确。  
回退：无法证明目标唯一时停止并报告，不猜测文件路径。

### 撤回

操作：作者从 Issue 找到发布提交，并运行辅助脚本。  
反馈：脚本校验目标与工作区，执行 Git revert 并推送；正常 Hugo 部署移除该条往来，Git 历史保留发布与撤回记录。  
回退：目标不明确、工作区不干净或推送失败时停止，不直接删除文件；作者可检查/重试标准 Git 操作。

## Edge Cases

- inbox 不是私有仓库时，安装或健康检查必须失败。
- 源码仓库可以公开或私有，但写入凭据只能授权该仓库。
- Issue 缺少必需结构、字段超长或来源无法验证时不得发布。
- 邮箱、IP、Turnstile token、内部标签与非 `/reply` 评论不得进入公开内容。
- 在 `publish` 之后才添加 `/reply` 不自动修改已发布内容；更新语义留待明确需求。
- 发布提交包含多个 Issue 时不得宣称支持单条安全撤回；实现必须保持一条 Issue 对应一条提交。
- 严格分支保护阻止直推时明确报错，并指向首版限制，不静默改走 PR。
- Git revert 冲突时脚本停止并保留 Git 的诊断信息，不强制覆盖用户内容。

## Acceptance Criteria

- 熟悉 GitHub 与 Cloudflare 的 Hugo 作者能按文档在约 20 分钟内完成首次测试来信。
- 访客无需登录；提交前可见“来信可能公开”提示。
- 原始私人字段不会出现在 Hugo 源码仓库、Action 公共日志或构建产物。
- 作者可只发布来信，也可在 `publish` 前加入一条 `/reply`。
- `publish` 直接推送净化 Markdown，不创建 PR，也不要求人工合并或手动 push。
- 相同 Issue 重复执行不会产生重复页面或重复往来。
- 默认 Hugo 模板不依赖 Epistle，并能通过标准模板/CSS 覆盖定制。
- 每条发布内容对应一个可从 Issue 访问的独立提交。
- 撤回只通过该提交的 Git revert 完成；辅助脚本会校验、revert、推送并留下可审计记录。
- 安装与升级引用语义化版本或已审阅提交 SHA，不静默跟随默认分支。
- 英文与简体中文 README 可互相切换，docs 使用同名文件结构且仓库内链接不跨语言。
